# Настройка Telegram мини-приложения

## Ответы на вопросы:

### 1. Смогут ли все заходить локально?
✅ **ДА** - каждый пользователь Telegram имеет уникальный `user_id`, который автоматически передается в заголовке `X-Telegram-User-ID`

### 2. Будет ли у них ваш Google аккаунт по умолчанию?
❌ **НЕТ** - каждый пользователь работает со своим `user_id` и своими данными

### 3. Смогут ли войти в свой Google аккаунт?
✅ **ДА** - Google Calendar опционален. Пользователь может:
- Работать БЕЗ Google Calendar (все сохраняется локально в SQLite)
- Подключить свой Google аккаунт через OAuth (опционально)

### 4. Как сохраняется календарь без Google?
✅ **В SQLite базе данных** - файл `backend/app.db`:
- Все события сохраняются с привязкой к `telegram_user_id`
- Каждый пользователь видит только свои события
- Работает полностью автономно

### 5. Можно ли использовать Telegram аккаунт?
✅ **ДА** - система использует `telegram_user_id` как основной идентификатор:
- При первом обращении автоматически создается пользователь в БД
- Все события привязываются к этому ID
- Google Calendar - это дополнительная опция для синхронизации

### 6. Какая база данных и подходит ли она?
**SQLite** - текущая БД:
- ✅ Подходит для локального запуска
- ✅ Подходит для небольшого количества пользователей (< 1000)
- ⚠️ Для продакшена с множеством пользователей лучше PostgreSQL

## Токен бота интегрирован

Токен добавлен в `backend/telegram_bot.py` по умолчанию.

## Запуск:

1. **Backend:**
```bash
cd backend
python app.py
```

2. **Telegram Bot:**
```bash
cd backend
python run_bot.py
```

3. **Для мини-приложения:**
- Настройте WebApp URL в @BotFather
- Укажите URL вашего backend (например, `https://your-domain.com`)

## Структура данных:

```
users (user_id) - уникальный Telegram ID
  ├── events - события пользователя
  └── oauth_tokens - токены Google (если подключен)
```

Каждый пользователь изолирован по своему `telegram_user_id`.
