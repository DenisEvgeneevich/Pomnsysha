# Архитектура системы для Telegram мини-приложения

## Идентификация пользователей

### Текущая система:
1. **Telegram мини-приложение**: Использует `telegram_user_id` из заголовка `X-Telegram-User-ID`
2. **Веб-версия**: Использует сессии через cookies (для локальной разработки)
3. **Telegram бот**: Использует `update.effective_user.id` напрямую

### Как это работает:

#### Для Telegram мини-приложения:
- Каждый пользователь Telegram имеет уникальный `user_id` (например, 123456789)
- При первом обращении к API автоматически создается запись в таблице `users`
- Все события привязываются к этому `user_id`
- **Google Calendar опционален** - можно работать и без него

#### Для локального запуска:
- Если запускать на `localhost`, то:
  - ✅ Каждый пользователь будет иметь свой уникальный `user_id` из Telegram
  - ✅ У них НЕ будет ваш Google аккаунт по умолчанию
  - ✅ Они смогут войти в свой Google аккаунт через OAuth (опционально)
  - ✅ Если не войдут в Google - календарь будет сохраняться локально в SQLite

## База данных

### SQLite (текущая):
- ✅ **Подходит для локального запуска** и небольшого количества пользователей
- ✅ Не требует настройки сервера БД
- ✅ Файл `app.db` хранится локально
- ⚠️ **Ограничения**: 
  - Не подходит для продакшена с множеством пользователей
  - Нет одновременного доступа из нескольких процессов
  - Медленнее при большом количестве данных

### Для продакшена рекомендуется:
- **PostgreSQL** или **MySQL** для множественных пользователей
- Или **SQLite** если пользователей < 1000

## Структура БД:

```sql
users (user_id PRIMARY KEY)
  └── events (user_id FOREIGN KEY)
  └── oauth_tokens (user_id FOREIGN KEY, provider='google')
```

## Поток работы:

1. **Пользователь открывает мини-приложение в Telegram**
   - Telegram автоматически передает `user_id` в заголовке
   - Система создает пользователя в БД (если его нет)

2. **Создание события:**
   - Событие сохраняется в локальную БД с `user_id`
   - Если пользователь подключил Google Calendar - событие синхронизируется

3. **Google Calendar (опционально):**
   - Пользователь может подключить свой Google аккаунт
   - OAuth токены хранятся в `oauth_tokens` с `provider='google'`
   - Синхронизация происходит автоматически

## Безопасность:

⚠️ **Важно для продакшена:**
- Telegram передает `user_id` в заголовке, но его можно подделать
- Для мини-приложения нужно использовать **Telegram WebApp Data** для проверки подлинности
- Текущая реализация подходит для локального тестирования

## Рекомендации:

1. **Для локального запуска**: Текущая система работает отлично
2. **Для продакшена**: 
   - Добавить проверку подписи Telegram WebApp Data
   - Использовать PostgreSQL вместо SQLite
   - Настроить HTTPS для OAuth callback
